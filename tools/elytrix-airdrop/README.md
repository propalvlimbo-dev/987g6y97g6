# ElytrixAirdrop — тестовая сборка

Патч оригинального JAR с SHA-256 `1ae338dae6e5ffb2ba819ecde808595f4500826f8b8b01f9e8262f1a0b493330`. Исходники не были доступны, изменённые участки оригинала подключены с помощью ASM. Сборка не проходила проверку на живом сервере; используйте только на тестовом сервере с резервной копией данных.

- Админ-меню: `/elytrixairdrop menu`; общий редактор 4 страницы по 45 ячеек, четыре категории с разными шансами. Все старые ID таблиц обращаются к одному пулу. Редактор сохраняет Bukkit ItemStack с метаданными.
- При первом запуске, если общего файла нет, из существующих `loot/peaceful.yml`, `fire.yml`, `sky.yml` и `sky_{common,rare,mythic,legendary}.yml` формируется `loot/common.yml`. Оригинальные файлы не изменяются. Если хотя бы в одной странице получается больше 45 предметов либо файл не читается, импорт блокируется и ошибка выводится в консоль; необходимо вручную объединить таблицы в `loot/common.yml`, предварительно сохранив резервные копии. Нет молчаливого обрезания.
- Игроки в радиусе 20 блоков по трём координатам (кроме spectator) определяют число наград: мирный 10/15/25, огненный и небесный 2/3/5 на каждый из максимум пяти контейнеров, при численности 0–3 / 4–6 / 7+. Для мирного подсчёт при открытии, для остальных при создании каждого контейнера. Предметы выбираются независимо по категориям: веса при 0–3 игроках 65/24/9/2, при 4–6 — 55/27/14/4, при 7+ — 45/30/18/7. Для набора от трёх предметов, если доступна хотя бы одна редкая категория, один из предметов выбирается из страниц 2–4. Одинаковые предметы не повторяются, пока пул уникальных предметов не исчерпан. Настройки `loot-min-items`/`loot-max-items` больше не определяют количество наград.
- Маски и исходная логика выдачи настоящих предметов сохранены, добавлена отмена drag и collect-to-cursor. Bossbar показывается всем и подключающимся игрокам, удаляется при окончании события/выключении.
- В меню доступны включение, длительность, радиус, время активации мирного и диапазон высот небесного, управление запуском/остановкой/телепортом и общий лут. Не все строки конфига редактируются через GUI; схема, отображаемое имя и голограмма остаются в YAML. Оригинальный автоспавн имеет фиксированный интервал 30 минут; старый `cooldown-minutes` в исходном планировщике не использовался, поэтому отдельный регулятор в меню не показан.

`build.sh` требует Java 21, ECJ, ASM, JAR API сервера и исходный JAR через переменные окружения, см. заголовок скрипта. Выполнены компиляция, проверка порогов и структуры JAR и JVM verification изменённых event-классов. Реальная сериализация предметов с метаданными, интеграция серверных плагинов, GUI и защиты на сервере ещё не проверены.

В этой версии используется 54-слотовая рамка из Elytrix-RP (`ꀀ`, как в `/menu`), поэтому для оформления нужен установленный серверный ресурс-пак. Мирная схема поднимается целиком на 2 блока; точка события, регион, координаты и восстановление используют поднятую позицию. Bossbar показывает этап, actionbar показывается игрокам в радиусе 20 блоков и отображает число присутствующих и примерный потенциал лута по числу игроков, не состав наград. Проверить в игре позицию схемы, текстуру меню, отображение таймеров и защиту `???`.

На живом Leaf/Paper не проверены создание настоящих предметов/эффектов и их сериализация/загрузка, поэтому сначала проверить на копии сервера после полного перезапуска и повторного перезапуска, вместе с редактором и выдачей лута во всех событиях.

Пёрл за стену, в другой мир или слишком высоко/низко отменяется, а не переносит на спавн. Сторонние плагины могут сами запрещать пёрл. Правила хоруса, пёрлов вне огненной схемы и воздушного события этим изменением не снимаются. Удерживаемый игрок также не может уйти за контур сверху/снизу или телепортироваться туда другим способом; движение и все причины телепорта проверяются на стороне сервера.

После смерти участник остаётся привязан к событию и при респавне возвращается на ближайший проверенный твёрдый блок схемы с двумя свободными блоками над головой (магма исключена), до окончания события. Если безопасное место найти не удалось, игрок освобождается для обычного респавна и в консоль пишется предупреждение: безопасность важнее удержания. Creative/spectator, остановка события и нестандартные принудительные действия других плагинов также являются исключениями; гарантировать абсолютную невозможность выхода нельзя. Лут после смерти и правила PvP не меняются. Следует проверить совместимость с плагинами респавна/античитом; при удержании есть риск повторной смерти на опасном событии.

Проверены выборочное снятие старого запрета только для участников, пёрл внутрь/наружу/в другой мир/выше и ниже арены, другие телепортации, удержание после смерти и безопасный fallback на заглушках, контроль байткода и JVM verification.
