# Shared `duel` world: experimental server test

This build is an experimental integration into the existing merged plugin, not a clean-room rewrite and not yet tested on a live Leaf server. Build with `SHARED_WORLD_EXPERIMENTAL=1`; the ordinary build continues to use world copies. Back up the world and both plugin data directories and test on a separate server first.

* The already-loaded `duel` world is used for every battle; a missing or differently named world fails closed. No duel world is copied, created, unloaded, or deleted in the patched instance-creation/cleanup paths. Existing old instance directories are not automatically deleted.
* Complete point pairs are assigned atomically by battle identity. Eight points give four candidate arenas. Incomplete pairs are skipped. Pair circles must not overlap (radius = half the distance between spawn points plus `protection.arena-margin`, default 20); a geometrically overlapping pair cannot be used while the other is occupied. If no pair is available participants are told to wait. The copied historical `spawns.yml` in this repository has six points, not eight; server-side data is authoritative.
* A reservation remains until battle return/cleanup, including while an online player's inventory return is being retried. A failed initial or next-round teleport invokes the existing return path before any remaining kit application and ends the scheduled start task with an error in the log. The original inventory backup system remains in use; offline restores depend on its normal join path.
* Spawn redirection, respawn and virtual bounds use the assigned pair, not a global world-keyed pair. Side boundaries are enforced for shared battles even if the old `protection.leave` setting is false. The mace kit retains no upper height limit; prolonged time above Y=104 gets the previously configured damage behavior.
* Direct player damage and player-shot projectiles cannot damage participants of another battle. Splash potion effects are filtered per battle. Lingering potions are disabled in `duel` to prevent clouds affecting adjacent battles. Projectiles shot by participants are removed when that battle is released. The original whole-world entity sweep between rounds is disabled. Player block placement/breaking, buckets, explosions, burning and piston protection use the existing instance protection on `duel`, so building is not supported there during this test. Other plugins can override event cancellation and still affect the world; use independent protection and backups.
* The legacy native matchmaking implementation does not preserve a player's position in its queue when a start fails; it informs them to wait and they may need to requeue. This build does not promise interoperability with arbitrary third-party teleport/world-edit/PvP plugins.

Verification done: simulated four concurrent reservations and fifth refusal, release/reuse, overlapping pairs, 1v1 and team respawn, player and potion isolation, missing world, teleport failure rollback hook, and existing boundary/mace/migration tests. The actual patched create/cleanup methods were executed with stubs and the absence of a copied directory checked. Modified classes were loaded under `-Xverify:all` against the Leaf API and bundled libraries from `/tmp/duel-leaf.jar`; helper code was also compiled against that API. This does not test the server, real gameplay, worlds, event priority interactions, real inventories or server shutdown. Test all of these with backups before production.
